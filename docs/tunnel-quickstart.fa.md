# راه‌اندازی نسخه آزمایشی OpenRoute Tunnel v0.2.0-alpha

**این نسخه واقعاً می‌تواند اتصال TCP نرم‌افزارهای پشتیبان HTTP CONNECT را از طریق یک گره خروجی قابل‌اعتماد و مجاز منتقل کند.** هنوز VPN کامل، اندروید یا تونل UDP بازی نیست. مسیریابی خودکار و بدون افت پینگ نیز پیاده‌سازی نشده است.

## پیش‌نیاز

- کامپیوتر ویندوز ۶۴ بیت یا لینوکس برای کلاینت
- یک کامپیوتر داوطلب دارای اتصال به اینترنت مقصد، که مالک آن اجرای گره خروجی را پذیرفته باشد؛ این گره می‌تواند کامپیوتر شخصی باشد و لازم نیست VPS بخرید
- ارتباط TCP از کلاینت تا گره خروجی روی یک پورت مشخص؛ عبور از فایروال، NAT و محدودیت‌های ISP تضمین نمی‌شود
- نصب باینری OpenRoute، یا Go 1.23 به بالا برای ساخت از سورس

## ۱. ایجاد گواهی‌ها (روی کامپیوتر امن خودتان)

```powershell
.\OpenRoute-Tunnel-Windows-x64-v0.2.0-alpha.exe init --dir identities
```

فایل‌های ایجادشده: `ca.crt`، `relay.crt`، `relay.key`، `client.crt` و `client.key`. گواهی‌ها کوتاه‌مدت‌اند (تقریباً سه ماه) و امضاهای آن‌ها TLS 1.3 را فعال می‌کند. **هرگز کلید خصوصی را در گیت‌هاب، تلگرام عمومی یا چت عمومی منتشر نکنید.**

به دستگاه گره خروجی فقط `ca.crt`، `relay.crt` و `relay.key` را منتقل کنید؛ به دستگاه کلاینت فقط `ca.crt`، `client.crt` و `client.key` را منتقل کنید. مسیر فایل‌ها در هر دو دستگاه باید در پوشه `identities` زیر برنامه باشد؛ می‌توانید `--identities` را تغییر دهید.

## ۲. اجرای گره خروجی داوطلب

برای آزمایش محلی (هر دو برنامه روی یک کامپیوتر):

```powershell
.\OpenRoute-Tunnel-Windows-x64-v0.2.0-alpha.exe relay --listen 127.0.0.1:9443 --allow example.org:443 --identities identities
```

برای دستگاهی که واقعاً به شما تعلق دارد یا با رضایت مالک آن قابل استفاده است، می‌توان `--listen 0.0.0.0:9443` را فقط بعد از تنظیم فایروال مناسب اجرا کرد. `--allow` باید مقصدهای **دقیق و از پیش تأییدشده** از قبیل `example.org:443,github.com:443` باشد. این نسخه عمداً پراکسی خروجی عمومی یا مقصدهای IP خصوصی را فعال نمی‌کند.

## ۳. اجرای کلاینت

روی کامپیوتر خودتان:

```powershell
.\OpenRoute-Tunnel-Windows-x64-v0.2.0-alpha.exe proxy --listen 127.0.0.1:8787 --relay IP_OR_HOST_OF_VOLUNTEER:9443 --identities identities
```

در نرم‌افزاری که HTTP CONNECT را پشتیبانی می‌کند پراکسی `127.0.0.1` با پورت `8787` را تنظیم کنید. آزمون نمونه با curl:

```powershell
curl.exe -v -x http://127.0.0.1:8787 https://example.org/
```

هر دو دستگاه باید گواهی‌های صادرشده از یک مجموعه را داشته باشند. **کلید خصوصی گره خروجی را به کلاینت و کلید کلاینت را به گره خروجی ندهید.** محدودیت یک کلاینت و مدیریت دستی گواهی فعلاً مناسب آزمایش خصوصی است، نه شبکه عمومی بزرگ.

## محدوده امنیت و عملکرد

- رمزنگاری و احراز هویت با کتابخانه استاندارد Go و TLS 1.3 انجام می‌شود، نه با الگوریتم رمزنویسی اختصاصی.
- گره خروجی مقصد و الگوی زمانی اتصال را می‌بیند؛ ترافیک HTTPS همچنان در سطح برنامه رمزنگاری‌شده باقی می‌ماند.
- فقط ترافیک نرم‌افزارهایی که صریحاً به پراکسی وصل شوند عبور می‌کند. UDP، DNS عمومی دستگاه، برنامه‌های بدون پشتیبانی از پراکسی و بازی‌ها **پوشش داده نمی‌شوند**.
- مقصد باید در allowlist گره خروجی وجود داشته باشد. سامانه از همه تحریم‌های حساب، پرداخت یا هویت عبور نمی‌کند.
- هیچ گره خروجی جهانی یا شبکه همتا‌به‌همتای خودکار ساخته نشده است. تونل TCP ممکن است نسبت به اتصال مستقیم کندتر باشد.
- پیاده‌سازی هنوز ممیزی امنیتی مستقل نشده؛ برای فعالیت حساس یا داده محرمانه روی آن حساب نکنید.
